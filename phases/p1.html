P1

Delivery phases · P1

Broker core MVP

P1 delivers a manual-insurer-assisted quote-to-policy lifecycle with correct broker and insurer boundaries. Automation of insurer APIs is not required. Correct state, evidence and ownership are — and they are what the gate measures.

Rendered from DELIVERY_PLAN.md §4, with the lifecycle and state machines from FLOWS.md §1, §6, §8 and §9 and the conceptual model from DOMAIN_MODEL.md §2.

THE RULE THIS PHASE EXISTS TO ENFORCE

A bind request records an instruction to seek or exercise authority for cover. Coverage is represented as confirmed only from retained evidence produced by the authority holder for that tenant and product arrangement — INV-005, INV-016 and INV-018. An application role does not grant authority to conclude an insurance contract.

01

Preconditions

Entry criteria

BT-G1 is recorded, independently

The security risk owner has recorded Security Ready on a proof run by someone other than its implementer. P1 puts real business records on the substrate; the substrate must already be proven, not promised.

The authority ADRs are accepted, not blocked

ADR-013 (who may create authoritative cover), ADR-017 (product, wording, rating and quote authority), ADR-006 (product versions), ADR-007 (broker versus insurer facts) and ADR-015 (effective and record time). Read each one's current row in the register; a row that reads BLOCKED_BY_S01 or DRAFT_REQUIRED is not an accepted one, and the binding code cannot be written to it.

The pilot tenant's authority profile is accepted

Slice S01 answered, for this tenant and product, whether every bind is REQUEST_ONLY or whether delegated or master-policy authority exists. The binding state machine cannot be built without that answer, and an agent may not infer it.

03

Execution order

The vertical slice is the order

The plan's acceptance path is twelve steps. Build them in that order, each as thin as it can be while still being real, and do not widen a step until the one after it runs. A wide P1.1 with no P1.10 behind it is a client database, not a broker core.

  1. Create tenant, create broker user — on the P0 substrate; no new tenancy code. If this needs a change to P0, P0 was not finished.
  2. Create client — P1.1, with the ownership baseline on the aggregate from the first migration.
  3. Capture risk — P1.3, and the snapshot rule that makes a submission immutable.
  4. Select a sourced distribution version — P1.4. This step decides whether provenance is a property of the model or a comment in it; build the insurer-owned side first.
  5. Submit risk — P1.5, with the transition table tested both ways.
  6. Record authority offers — P1.6. Three concepts. The temptation is one table with a kind column; that is how an indication becomes a quote in a report.
  7. Compare and recommend — P1.7, P1.8, with the disclosures.
  8. Record client acceptance — P1.9.
  9. Request bind — P1.10, the state machine up to PENDING_CONFIRMATION. Stop and test: nothing so far means insured.
  10. Record authority-supported cover — P1.10, the CONFIRMED transition and its evidence requirements, per the accepted authority profile.
  11. Register the broker policy representation — P1.11, referencing the bind, the evidence and the versions.
  12. Documents, audit, portal — P1.12 alongside every step above; P1.13 last, driven by the contracts. Then the trace, end to end, for BT-G2.
04

What the agent codes

State that cannot lie about authority

Every state machine in P1 follows the contract template: a transition table, preconditions, emitted events, and the failure signature the Architect stage names — one field asked to carry several independent states. The binding rules below are the ones a reviewer checks first, because they are the ones the whole broker-versus-insurer boundary rests on.

  • REQUESTED, AUTHORITY_RESOLVED, SENT_TO_AUTHORITY, REFERRAL_REQUIRED and PENDING_CONFIRMATION do not mean insured. No read model, document or portal screen may render them as cover
  • CONFIRMED requires the accepted authority-agreement or profile reference, the source identity, effective start and end, recorded time and retained evidence — as mandatory fields, not optional ones
  • Under REQUEST_ONLY, only insurer-authoritative evidence can confirm. A broker user with the binding:confirm permission and no applicable authority profile is denied, and the denial is audited
  • Under delegated or master-policy authority, the command proves product, territory, limit, period and referral constraints before confirmation; outside any one of them the state is REFERRAL_REQUIRED
  • Duplicate confirmations are idempotent; conflicting ones go to manual review. The latest message does not silently win
  • Policy registration references the completed bind order, the coverage evidence and the sourced product and wording versions
  • Every transaction pins the versions it used — product, wording, pricing and commission rule — so it can be reproduced exactly later (INV-006)
  • Every material transition emits an event with the minimum metadata of ARCH-001 §12, including the authority reference when the fact asserts delegated authority
A domain reviewer is not optional in P1

The Build stage lists a domain reviewer who must not be skipped because a change looks technical. In P1 every change is domain. The reviewer is someone who has placed insurance, and their review is scenario-based: they walk a bind under this tenant's arrangement and say whether the states mean what the business means.

Stop signal: something confirms cover from a user action

A button, a status change or an import that reaches CONFIRMED without authority evidence is the failure this phase exists to prevent, whatever it is called in the interface.

Stop signal: a price the broker computed is labelled a quote

It is an indication. The label is the defect; the fix is in the model, not the wording.

Stop signal: a product version was edited in place

Every prior transaction that pinned it is now unreproducible. Versions are immutable; changes are new versions.

Stop signal: an insurer's status is simulated

A broker-side record that asserts an insurer decision the insurer never made is a fabricated fact, however convenient for the demo.

07

Halt

Stop conditions

  • The tenant authority profile for the pilot tenant is not accepted — the binding machine has no arrangement to implement
  • ADR-013 or ADR-017 is still BLOCKED_BY_S01 or DRAFT_REQUIRED
  • Any path reaches CONFIRMED without authority evidence, or renders an earlier state as cover
  • An insurer adjudication, acceptance or issuance is simulated on the broker side
  • Scope drifts into P2 — a placement workspace, a claim, a renewal — inside a P1 package
  • A domain reviewer was skipped on a change that touches state, provenance or disclosures
